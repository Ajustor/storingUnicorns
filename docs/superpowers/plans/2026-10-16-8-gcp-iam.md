# Authentification IAM GCP pour Cloud SQL (PostgreSQL / MySQL) — spec et plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal (v0.15.2):** se connecter à Cloud SQL PostgreSQL / MySQL avec son compte
Google (authentification IAM de base de données), sans mot de passe ni proxy :
l'app obtient le jeton via `gcloud` et le renouvelle avant expiration.

**Rappels GCP :** l'IAM de Cloud SQL ne concerne que PostgreSQL et MySQL.
Utilisateur PostgreSQL = adresse complète (`prenom.nom@domaine.com`, ou pour un
compte de service `sa@projet.iam` sans `.gserviceaccount.com`) ; MySQL = partie
avant `@` (compte de service : nom avant `@`). Le jeton OAuth2 est envoyé comme
mot de passe ; TLS obligatoire ; MySQL exige le plugin `mysql_clear_password`
(sqlx : `MySqlConnectOptions::enable_cleartext_plugin(true)`). Durée ≈ 1 h.

Branche : `feat/gcp-iam` depuis master (0.15.1).

## Contrat d'API (partagé moteur / interface)

`src/engine/models/connection.rs` :
```rust
/// How a PostgreSQL / MySQL connection authenticates.
#[derive(Debug, Clone, Copy, Serialize, Deserialize, PartialEq, Eq, Default)]
pub enum DbAuthMethod { #[default] Password, GcpIam }
impl Display: "Mot de passe" / "IAM Google Cloud"
// ConnectionConfig : #[serde(default)] pub db_auth: Option<DbAuthMethod>,  // None = Password
impl ConnectionConfig { pub fn effective_db_auth(&self) -> DbAuthMethod }
```
`src/engine/db/gcp_iam.rs` :
```rust
/// Check the form: GcpIam needs a user (French messages).
pub fn validate(db_type: &DatabaseType, username: &str) -> Result<(), String>;
/// The database user name the IAM account must use for this engine
/// (PostgreSQL: as typed; MySQL: the part before '@'), for a form hint.
pub fn database_user(db_type: &DatabaseType, account: &str) -> String;
```
Règles : `GcpIam` seulement pour `Postgres` / `MySQL` ; force au moins
`SslMode::Require` (affiché ajusté, comme une note).

### Task 1 (moteur) : jetons et connexion
- [ ] Modèle selon le contrat ; aller-retour TOML ; ancien fichier sans
  `db_auth` → `Password`.
- [ ] `gcp_iam.rs` : fournisseur de jeton
  - commande `gcloud sql generate-login-token` (repli `gcloud auth
    print-access-token` si la sous-commande n'existe pas) ; Windows via
    `cmd /C gcloud` (comme `run_az` dans `azure.rs`) ; délai 30 s ;
  - cache mémoire par compte (+ échéance ≈ 55 min, ou `exp` du jeton si

  - erreurs traduites : gcloud absent (« gcloud introuvable : installe le SDK
    Google Cloud ou ajoute-le au PATH »), session expirée / non connecté

    raccourci, sans jeton ;

    traduction des erreurs, échéance) ; exécution de commande injectable.
