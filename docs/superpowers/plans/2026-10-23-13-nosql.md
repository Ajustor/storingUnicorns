## Décisions d'architecture
1. **Deux nouveaux moteurs, une famille.** `DatabaseType::MongoDB`, `DatabaseType::Redis`
   + `DatabaseType::family() -> Family { Sql, Document, KeyValue }` et `is_sql()`.
   Tout code SQL teste `is_sql()` (garde-fous listés plus bas).
2. **Catalogue réutilisé, exécution séparée.** Les méthodes de *métadonnées*
   de `DatabaseConnection` aiguillent vers les moteurs NoSQL (Mongo :
   `get_tables_by_schema` = bases → collections, `get_table_column_details` =
   champs échantillonnés, `get_indexes`, `get_primary_keys` = `["_id"]`, FK =
   vides ; Redis : une `SchemaInfo` `db0`…`db15` par base, `tables` vide). Ainsi
   explorateur, Ctrl+N, schémas masqués (= bases masquées), `ops::schema::table_details`
   et la complétion par colonnes fonctionnent sans changement. Les méthodes
   d'*exécution SQL* (`execute_query*`, `execute_transaction`, `execute_checked_batch`,
   `execute_tsql_batch`) renvoient l'erreur `not_sql(db)` : « Opération SQL
   indisponible pour MongoDB ». L'API NoSQL passe par `conn.mongo()` / `conn.redis()`.
3. **Noms de collection** : `quote_chars` renvoie `('"','"')` pour Mongo / Redis ;
   les clés de session restent `"db"."coll"` (`qualified`) et `split_qualified`
   garde les points d'une collection entre guillemets (`"shop"."fs.chunks"`).
   `mongo::CollectionRef::parse` accepte cette forme ou `db.coll` (coupé au
   premier point : un nom de base ne contient pas de point).
4. **Grille = champs de 1er niveau aplatis.** Colonnes : `_id` d'abord puis les
   champs dans l'ordre de première apparition sur la page ; cellules : texte
   brut pour les chaînes, nombres, booléens, dates ISO 8601 (`2024-01-02T03:04:05.678Z`) ;
   syntaxe shell compacte pour objets / tableaux / types spéciaux
   (`ObjectId("…")`, `{a: 1}`) ; `null` = `NULL_CELL` ; champ absent =
   `ABSENT_CELL` (affiché « — » grisé). `_id` est la clé primaire
   (`QueryResult.primary_key = ["_id"]`) : `PendingEdits` / `RowChanges` sont
   réutilisés, puis convertis en opérations Mongo par une fonction pure.
5. **Console NoSQL à part** : `nosql::run_script` (jamais `ops::query::*`), avec
   une `NoSqlScope` (base courante : `use shop`, `SELECT 3`) et une liste de
   commandes destructives à confirmer **avant** l'envoi (`nosql::warnings`).
6. **Pas de mode transaction manuel, pas de DDL, pas de « Structure… », pas de
   FK** pour NoSQL : masqués dans les deux interfaces. Export / import : JSON,
   JSON Lines **et CSV** (décision utilisateur), via l'interface de transfert
   existante ; le CSV réutilise `export_to_csv` / `parse_csv`.
7. **Redis** : un `ConnectionManager` (reconnexion auto) par base parcourue ;
   chaque exécution de console ouvre sa propre connexion (MULTI/EXEC, `SELECT`
   et `WATCH` y restent confinés). `KEYS motif` est exécuté par un `SCAN MATCH`
   itératif (non bloquant). Valeurs binaires : UTF-8 si valide, sinon échappées
   comme redis-cli (`"\xff\x00"`), et relues par le même parseur.
8. **TLS** : `ssl_mode` / `ssl_ca` réutilisés : `None`/`Disable`/`Prefer` →
   sans TLS ; `Require` → TLS sans vérifier le certificat ; `VerifyCa`/`VerifyFull`
   → TLS vérifié (+ CA supplémentaire). Le schéma de l'URI prime
   (`mongodb+srv://` et `rediss://` activent TLS, `tls=false` le coupe).
   Mongo + rustls utilise les racines Mozilla : sans `ssl_ca`, le moteur
   exporte les racines du système (`rustls-native-certs`) dans
   `<app_dir>/mongo-roots.pem` et le passe en `ca_file_path` (proxys d'entreprise).

## Syntaxe Mongo (`mongo/shell.rs`, parseur écrit à la main, sans JS)
- **Unités** : séparées par `;` ou par un saut de ligne à profondeur 0 sauf si
  la ligne suivante commence par `.` (chaînage `.sort()` à la ligne). Commentaires `//`, `/* */`.
- **Commandes** : `use <db>`, `show dbs`, `show collections`,
  `db.<coll>` | `db.getCollection("…")` | `db["…"]` puis `.find(f?, proj?)`,
  `.findOne(f?, proj?)`, `.aggregate([..], opts?)`, `.countDocuments(f?)`,
  `.estimatedDocumentCount()`, `.distinct("champ", f?)`, `.insertOne(d)`,
  `.insertMany([..], opts?)`, `.updateOne/updateMany(f, u | [pipeline], {upsert}?)`,
  `.replaceOne(f, d, {upsert}?)`, `.deleteOne/deleteMany(f)`,
  `.createIndex(keys, {name, unique, sparse, expireAfterSeconds, partialFilterExpression, hidden}?)`,
  `.dropIndex("nom" | keys)`, `.getIndexes()`, `.drop()` ; modificateurs de
  `find` : `.sort(d)`, `.limit(n)`, `.skip(n)`, `.projection(d)`, `.count()`
  (→ countDocuments), `.toArray()` / `.pretty()` ignorés ; `db.createCollection("n", opts?)`,
  `db.dropDatabase()`, `db.getCollectionNames()`, `db.runCommand({..})`,
  `db.adminCommand({..})`. Méthode inconnue → « Méthode non prise en charge :
  … (utiliser db.runCommand) » ; option inconnue → erreur.
- **Valeurs** : objets (`{a: 1, "b.c": 2, $gt: 3, 'x': 4}`, virgule finale
  admise), tableaux, chaînes `"…"`/`'…'` (`\n \t \r \b \f \\ \' \" \/ \uXXXX \xHH`),
  nombres (entier → Int32 s'il tient, sinon Int64 ; décimal/exposant → Double ;
  `0x…`, `Infinity`, `NaN`, signe), `true false null`, regex `/…/imxs`,
  constructeurs avec `new` optionnel : `ObjectId("hex")` / `ObjectId()`,
  `ISODate("…")` / `Date("…" | ms)` / `Date()`, `NumberLong(n|"n")`,
  `NumberInt(n)`, `NumberDecimal("…")` / `Decimal128("…")`, `UUID("…")`,
  `BinData(sub, "b64")`, `Timestamp(t, i)`, `MinKey()`, `MaxKey()`,
  `RegExp("p", "f")`. Un objet dont toutes les clés sont des clés JSON
  étendu (`$oid`, `$date`, `$numberLong`, `$binary`…) est converti en type
  BSON (via `bson` + `serde_json`) : la sortie de mongoexport se relit.
- **Erreurs** : `ParseError { message (FR), offset }` → l'interface place le curseur.
- **Impression** `to_shell(&Bson, pretty)` : inverse exacte, propriété testée
  `parse_value(to_shell(v)) == v` pour tous les types.
- **Danger** (`danger(&MongoCommand) -> Option<String>`) : `deleteMany({})`,
  `updateMany({}, …)`, `drop()`, `dropDatabase()`, `dropIndex("*")`,
  `runCommand`/`adminCommand` dont la 1re clé est `drop`, `dropDatabase`,
  `dropIndexes`, `shutdown`, `renameCollection`.
- **Résultats** : find/aggregate/getIndexes → `flatten` (+ `Source::Collection`
  pour un `find` sans projection excluant `_id`) ; écritures → `rows_affected`
  et colonne `résultat` (« 1 inséré, _id ObjectId(…) », « 3 correspondants,
  2 modifiés ») ; count → 1 cellule ; distinct → colonne `valeur` ; runCommand
  → document aplati. `limit` de console = `max_rows` (1000), `truncated` posé.

## Syntaxe Redis (`redis/cli.rs`)
- Une commande par ligne ; lignes vides et commençant par `#` ou `//` ignorées.
  Jetons séparés par des blancs ; `"…"` avec `\" \\ \n \r \t \b \a \xHH` ;
  `'…'` littéral (seul `\'`) ; un guillemet fermant doit être suivi d'un blanc ou
  de la fin de ligne ; guillemets non fermés → erreur (règles de redis-cli).
- `classify(argv) -> Safety { Safe, Confirm(String), Refuse(String), RewriteScan }` :
  **Refuse** SUBSCRIBE, PSUBSCRIBE, SSUBSCRIBE, MONITOR, SYNC, PSYNC, et les
  commandes bloquantes avec délai 0 (BLPOP, BRPOP, BLMOVE, BLMPOP, BZPOPMIN,
  BZPOPMAX, BZMPOP, XREAD/XREADGROUP `BLOCK 0`, WAIT … 0) ; **Confirm**
  FLUSHALL, FLUSHDB, SHUTDOWN, DEBUG, SWAPDB, MIGRATE, REPLICAOF/SLAVEOF,
  FAILOVER, CONFIG SET/REWRITE/RESETSTAT, SCRIPT FLUSH, FUNCTION
  FLUSH/DELETE/RESTORE, CLIENT KILL/PAUSE, ACL SETUSER/DELUSER, MODULE
  LOAD/UNLOAD, CLUSTER * ; **RewriteScan** KEYS (→ SCAN MATCH COUNT 1000
  jusqu'à `max_rows`, note « KEYS exécuté avec SCAN »).
- `SELECT n` change `scope.database` pour la suite du script et des exécutions suivantes de la console.
- `reply_to_result(argv, Value)` : nil → NULL ; entier / statut / chaîne → 1
  colonne ; tableau → `#, valeur` ; paires (HGETALL, CONFIG GET, HRANDFIELD
  WITHVALUES, Z*RANGE* WITHSCORES, ZPOP*, réponses de HSCAN/ZSCAN) → 2
  colonnes ; *SCAN → lignes + « curseur suivant : n » ; XRANGE/XREVRANGE → `id,
  champs` ; INFO → `section, clé, valeur` ; map RESP3 → 2 colonnes. Lecture d'une
  clé (GET/HGETALL/LRANGE/SMEMBERS/ZRANGE/XRANGE sur une seule clé) →
  `Source::Key` (éditable).

## Risques
- **Taille / temps de build** : `mongodb` (+ hickory) et `redis` ajoutent
  ~100 crates ; vérifier la taille du binaire release (`opt-level = "s"`).
- **Fournisseur crypto rustls** : un seul (`ring`) doit être compilé.
- **Compatibilité** : Cosmos DB (pas de `$sample` sur certaines versions → repli
  `find().limit`), DocumentDB (pas de `listDatabases` restreint, `retryWrites=false`
  dans l'URI), utilisateurs sans droit `listDatabases` (repli base par défaut),
  Redis managés sans `CONFIG`/`INFO` (repli 16 bases), `TYPE` de modules
  (`ReJSON-RL` → `Other`, lecture seule).
- **Volume** : grandes bases Redis (SCAN limité, jamais KEYS), collections
  énormes (`countDocuments` lent → `estimatedDocumentCount` sans filtre,
  `maxTimeMS` 30 s sur le compte).
- **Écritures non atomiques** : un Submit Mongo est séquentiel (les transactions
  exigent un replica set) ; l'erreur indique ce qui a été appliqué.

## Décisions de l'utilisateur (2026-10-23)
1. Mots de passe : comme les autres connexions (`config.toml`).
2. Hors v1 : Redis Cluster / Sentinel, authentification Mongo X.509 / AWS /
   Kerberos, BSON binaire (mongodump). **CSV inclus** (export et import, Mongo
   et Redis, voir contrat `TransferFormat` / `ImportOptions`).
3. TLS Mongo : racines du système exportées en PEM par défaut (décision 8).
